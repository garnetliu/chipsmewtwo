## 裁决规则

prototype 是视觉与交互的基准。遇到它和现有代码、现有文档说法不一致时，顺序判断，命中就停：

1. **prototype 画了、别处说的不一样 → 按 prototype。**
2. **prototype 没画 → 按现有代码已实现的做法。** prototype 只画了九个视图，
   没画首页 `/`。没画不等于否定，`app/page.tsx` 现有的首页导航页保留。
3. **prototype 因为演示数据只有 9 条而做的简化 → 两边都不按，按真实规模做。**

第 3 档只有下面四项，别往里塞别的：

| prototype 里的简化 | 实际怎么做 | 为什么 |
|---|---|---|
| 四个列表页都没有分页 | 保留分页 | 演示只有 9 条不需要翻页。真实数据 1025 只 Pokémon、800+ 招式、156 个道具，必须分页。`components/pagination-list` 已经做好并接上了地址栏 |
| 性格只列了 7 种 | 25 种全列 | 游戏里就是 25 种 |
| 模拟器用 9 个按钮的网格选 Pokémon | 换成带搜索的 select | 按钮网格放不下 1025 只 |
| 世代筛选默认选中某一代（精灵默认 Gen 1、道具默认 Gen 2） | 首次进入不选中，展示全量 | prototype 自己的空态文案写着「演示数据集中在 Gen 1，请切换筛选查看」—— 默认选中是为了让演示有内容。真实数据全世代都有 |

## 任务怎么写

每条固定三段，缺一段就是没写完：

- **改哪里** —— 具体文件路径，新建的标「新建」
- **达到什么效果** —— 具体到 UI 元素、字段、数值、文案。不写「按 prototype 做」，
  要把 prototype 里的形态直接描述出来
- **怎么算验证通过** —— 可执行的命令，或者可断言的具体值。不写「xxx 可验」这种话

## 全局口径

下面几条贯穿所有任务，各条任务不再重复说明。

**数据只来自本地库。** 运行时只查本地 Postgres，不回源 PokeAPI。外部数据源只在
`pnpm seed:refresh` 时接触，不在请求路径上。

**单端点 GraphQL。** 所有数据走 `POST /api/graphql` 一个端点，没有 REST 端点。
字段契约在 `graphql/schema/*/schema.graphql`。

**错误语义分两层。** 查不到某一条 → 返回 `null`，不算错误，前端展示「未找到该 X」。
真出错（库连不上、参数非法）→ 进 GraphQL `errors` 数组，带 `extensions.code`。
HTTP 状态码一律 200。前端靠「字段是不是 null」区分空态与故障，不解析 errors。

**列表分页用 offset/limit，不用 cursor。** `(offset: Int!, limit: Int!)` 配
`PaginationMeta { page, pageSize, total, totalPages, hasNext, hasPrev }`，四个列表页共用。
资料是静态的，cursor 要解决的「翻页时数据在变」这里不存在；而「跳到第 5 页」「共 1025 条」
是资料站真需要的。

**详情页服务端渲染，列表页客户端取数。** 四个详情页用 RSC 在服务端取数 ——
爬虫和禁用 JavaScript 的客户端请求详情页时，服务端返回的 HTML 里必须已经包含对象名称和
正文资料，不依赖客户端脚本二次获取。四个列表页的筛选与翻页走客户端 Apollo，响应更快。
两条路都已搭好：`graphql/apollo/server.ts`（RSC）与 `graphql/apollo/client.ts`（浏览器）。

**重字段只在详情页取。** 种族值、进化链、登场版本、招式的世代数值表这类「一行变几十行」
的字段不进列表页查询。库里一只形态有几十个版本 × 十种语言的行，列表页整页一起查会拉出上千行。

**筛选与分页都放进 URL 查询参数。** `/pokemon?gen=9&page=2` 这种形式，四个列表页一致。
刷新保留、链接可分享。参数名统一用 `gen` 和 `page`，不许某个域自己叫 `generation`。

**路由的 `[name]` 段传英文 slug**（`bulbasaur`、`razor-leaf`），不是中文名。
`Pokemon.slug` / `Move.slug` / `Item.slug` / `Ability.slug` 在库里都是唯一键。

**视觉口径：版式照 prototype，配色字体用仓库现有的。** prototype 的
`--primary: #3b7dd8` 蓝、苹方中文字体栈、无暗色模式这三项不照搬。`app/globals.css` 现有的
紫色系品牌色、Inter / Space Grotesk / JetBrains Mono 三套字体、暗色模式全部保留。
prototype 里布局、卡片、chip、徽章、数据表格、种族值条、hover 抬升这些形态照做。

**首版没有登录。** 所有页面公开可见，没有收藏、没有个人数据、没有权限、没有后台管理。
