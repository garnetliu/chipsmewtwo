- [x] **T13 设计 token 与基础件**

  **改哪里**：`app/globals.css` 加 token，新建 `components/pokedex/` 放六个基础件

  **达到什么效果**：prototype 用了一套资料站专用的视觉元素，现有 shadcn token 里没有。

  补进 `app/globals.css` 的 token：

  - **18 种属性色** —— prototype 只给了 10 种：草 `#4cae6c`、毒 `#9b59d0`、火 `#e8703a`、
    水 `#3b7dd8`、飞行 `#7fa6e8`、电 `#e0b52c`、地面 `#b8a24a`、一般 `#8a94a8`、
    超能力 `#e05c8a`、虫 `#8aa83c`。其余 8 种（格斗、岩石、幽灵、龙、恶、钢、冰、妖精）
    按同一明度饱和度补齐，相邻两种肉眼要能分开
  - **版本色** —— 红 `#e03e3e`、绿 `#3d9b62`、蓝 `#3b7dd8`、黄 `#f2c531`、
    金 `#c9a227`、银 `#8a94a8`，其余版本按同一风格补
  - **种族值条三档阈值色** —— 值 ≥100 用 success 绿、≥80 用主色、其余用 warning 黄

  六个基础件，形态照 prototype 的 CSS 复刻，颜色一律走 CSS 变量：

  | 件 | 形态 |
  |---|---|
  | `VerBadge` | 版本色块。最小宽 1.5rem、高 1.25rem、圆角 6px、字号 10px、粗体、白字 |
  | `TypeTag` | 属性胶囊。高 1.375rem、左右内边距 0.55rem、全圆角、字号 11px、白字 |
  | `GenChip` | 筛选 chip。高 2rem、左右内边距 0.85rem、全圆角、白底灰边；选中态实心主色、白字、带主色投影 |
  | `Card` | 圆角 12px、1px 边框、极淡投影（`0 1px 2px rgba(23,32,58,.05)`） |
  | `DataTable` | 表头 12px 灰底、内边距 0.65rem 1rem；行 13px、内边距 0.75rem 1rem、上边框 1px |
  | `PokeCard` | 在 Card 基础上加 hover：上移 2px、投影加深，0.15s 过渡 |

  暗色模式下背景和文字对比度不能塌 —— 属性色和版本色是固定的品牌色不随主题变，
  但它们的容器底色、边框、文字要跟着主题走。

  **怎么算验证通过**：
  1. `pnpm build` 通过
  2. 起一个临时页面把六个件各渲染一次，亮色和暗色两个模式都看一遍：
     暗色下文字可读、边框可见、卡片和页面背景能区分开
  3. 18 种属性各渲染一个 TypeTag，没有两种颜色肉眼难分
  4. `grep -c '\-\-color-type-' app/globals.css` 不少于 18
  5. `grep -n '#3b7dd8' app/globals.css` 只出现在属性色「水」那一处，没有变成 `--primary`
  6. `grep -rn 'PingFang' app/ components/` 零命中（字体栈没被替换）
  7. 现有的暗色切换按钮还能用，切过去六个件都正常

- [x] **T15 世代筛选器**

  **改哪里**：新建 `components/pokedex/gen-filter.tsx`

  **达到什么效果**：一行 Gen1–Gen9 的单选 chip。左侧一个「世代筛选」标签，
  右端一句「单选筛选 · 当前共 N 条结果」。整行装在一张 Card 里，内边距上下 1rem、左右 1.25rem。

  chip 文案只写「Gen 1」**不带版本名**。prototype 写的是「Gen 1 · 红/绿/蓝」，
  九个全带版本名会把这一行撑到换行两次。

  行为：

  - 选中状态进 URL 查询参数 `?gen=3`，刷新保留
  - **首次进入（URL 上没有 `gen`）时九个都不选中，列表展示全量**
  - 再点一次当前选中项 → 取消筛选，`gen` 参数从 URL 移除，回到全量
  - 请求进行中重复点同一项不产生错误、不出现错误边界

  **怎么算验证通过**：
  1. 点 Gen 3，地址栏变成 `?gen=3`，列表刷新
  2. 刷新页面，Gen 3 仍选中，列表还是筛过的
  3. 再点一次 Gen 3，地址栏的 `gen` 参数消失，列表回到全量
  4. 首次进入（无 query）时九个 chip 都不是选中态
  5. 连点同一个 chip 五次，页面不报错、不出现错误边界
  6. 九个 chip 在 1280px 宽度下排成一行不换行

- [x] **T16 列表页壳**

  **改哪里**：新建 `components/pokedex/list-shell.tsx`，内部复用现有的
  `components/pagination-list`

  **达到什么效果**：四个列表页共用的外壳，包三部分：

  - **页头** —— 左边是标题（26px 粗体）+ 「P0 · 核心资料」徽章（主色淡底、圆角全、11px）
    + 下面一句灰色说明；右边是统计块，每项上面是数值（20px 粗体、等宽数字）
    下面是 11px 灰色标签，项与项之间一条 1px 竖分隔线
  - **筛选行** —— T15 的组件（特性列表页不传，那页没有筛选）
  - **内容区 + 分页** —— 分页用现有的 `components/pagination-list`，
    已经接好了地址栏的 `page` 参数

  四种状态：

  | 状态 | 表现 |
  |---|---|
  | 加载中 | 骨架屏，**不带任何文案**。骨架的高度和真实卡片一致，切换时不跳动 |
  | 空 | 居中卡片，14px 粗体「当前筛选条件下暂无结果」，下面一行 12px 灰字提示换个筛选 |
  | 失败 | 居中卡片，「列表加载失败，请稍后再试」+ 重试按钮，点击重新发请求 |
  | 正常 | 渲染 children |

  分页保留 —— prototype 没画分页是因为演示只有 9 条，真实数据必须翻页。

  **怎么算验证通过**：
  1. 正常态：`/pokemon` 能看到页头、筛选行、卡片、分页四块
  2. 空态：筛一个没有数据的组合，出现「当前筛选条件下暂无结果」
  3. 失败态：把 GraphQL 端点地址改错，出现「列表加载失败，请稍后再试」和重试按钮，
     点重试会重新发请求（网络面板里能看到）
  4. 加载态：浏览器 throttle 到 Slow 3G 打开列表，先看到骨架屏；
     数据到达后卡片位置和骨架位置一致，页面不跳动
  5. 分页点第 2 页，地址栏 `?page=2`，刷新还在第 2 页
  6. 筛选和分页同时用：`?gen=1&page=2` 两个参数都在，都生效

- [x] **T17 详情页壳**

  **改哪里**：新建 `components/pokedex/detail-shell.tsx`

  **达到什么效果**：四个详情页共用的外壳。

  **面包屑按 prototype 的行为：返回来源页，不是固定回列表。**
  形如「← 返回特性详情 / 精灵详情 / 妙蛙种子」，第一段是可点的主色链接，
  文案随来源变：从特性详情进来写「← 返回特性详情」，从列表进来写「← 返回精灵列表」，
  从搜索进来写「← 返回搜索结果」。这需要维护一个来源栈 —— prototype 用的是
  `navStack.push` / `pop`，Next 里用 URL 查询参数或 sessionStorage 都行，
  但刷新页面后要能退化成「回对应列表」而不是崩掉。

  另外包四种状态：

  | 状态 | 表现 |
  |---|---|
  | 未找到 | 居中卡片「未找到该 Pokémon / 招式 / 道具 / 特性」+ 返回列表按钮 |
  | 加载失败 | 「X 资料加载失败，请稍后再试」+ 重试，面包屑始终可用 |
  | 说明为空 | 渲染「说明暂缺」。库里 `shortEffect`、道具 `descriptions` 本来就可空 |
  | 图片异常 | 图片加载失败或字段为 null 时用占位图，**卡片高度不变、布局不塌** |

  **怎么算验证通过**：
  1. 从 `/ability/overgrow` 点进妙蛙种子详情，面包屑写「← 返回特性详情」，
     点击回到 `/ability/overgrow`
  2. 从 `/pokemon` 点进妙蛙种子详情，面包屑写「← 返回精灵列表」，点击回到 `/pokemon`
  3. 在第 1 步的页面上刷新，面包屑退化成「← 返回精灵列表」，点击能用，不报错
  4. 访问 `/pokemon/not-a-real-slug`，显示「未找到该 Pokémon」和返回列表按钮
  5. 传一个空说明进去，渲染出「说明暂缺」
  6. 把图片 src 改成 404 地址，占位图出现，卡片高度和正常时一致
